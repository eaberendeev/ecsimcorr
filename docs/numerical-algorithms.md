# Численный шаг, границы и балансы

Карта реализации: оркестрация находится в `SimulationEcsim::make_step()` и
`SimulationEcsimCorr::make_step()`. Геометрия и выбор взаимодействия —
`utils/particle_path.h`; физические условия — `utils/boundary_conditions/`;
депозит — `algorithms/decompose_esirkepov_current.h`.

## Временные уровни

`fieldE/fieldB` содержат поля начала шага, `fieldEn/fieldBn` — конца шага,
`fieldEp` — предиктор электрического поля на полушаге. В gather прибавляются
внешнее электрическое поле и начальное магнитное поле. `SHAPE` (response)
связывает gather, предикторный ток и L-матрицу; `SHAPE_CH` (charge) связывает
плотность и Esirkepov-ток. Начальная плотность использует тот же shape, что и
плотность последующих шагов.

В ECSIM координаты сдвинуты относительно скоростей на полшага:
`x_(n-1/2) → x_(n+1/2)` при скорости `v_n`. После применения границ
предсказываются ток, L-матрица и `E'_(n+1/2)`, обновляется скорость,
вычисляются плотность и поля конца шага.

В ECSIM-Corr координаты и скорости заданы на целых шагах:

1. Депонировать `rho_n`, сдвинуть частицу на `dt/2` при `v_n`, депонировать
   ток первой половины. Применить сохранённые граничные решения и только
   затем перераспределить оставшиеся частицы по ячейкам.
2. На `x_(n+1/2)` собрать предикторный ток и L-матрицу; решить СЛАУ для
   `fieldEp` с теми же граничными ограничениями, что и у оператора.
3. Выполнить Boris за полный `dt`, затем второй сдвиг на `dt/2` при новой
   скорости. Депонировать второй ток и сохранить решения о границах.
   Полусумма токов двух половин имеет нормировку полного шага.
4. Исправить электрическое поле по Esirkepov-току. Скорости сорта умножить
   на `lambda`, определяемую разностью работы исправленного тока и Boris.
   Решения о поглощении/отражении приняты до этого изменения скорости.
5. Применить сохранённые решения, перераспределить частицы, депонировать
   конечную плотность и обновить магнитное поле. Вторичные частицы добавляются
   после депозитов и участвуют в следующем шаге.

## Траектория у стенки

Для пробного прямого движения `x(t) = start + t*(trial_end-start)`, `0 ≤ t ≤ 1`,
выбирается первая пересечённая непериодическая грань. `BoundaryCrossing`
содержит грань, `t_hit`, точку и судьбу частицы. Пространственный критерий
отражения проверяется в точке попадания, энергетический — по входящей
скорости. Порядок разных граней в JSON не определяет первую стенку.
При точном одновременном попадании действует фиксированный геометрический
порядок X, Y, Z, цилиндр; отдельная модель взаимодействия с ребром не задана.

При поглощении ток заканчивается на стенке. При отражении депонируются
два отрезка: до стенки и от неё до зеркального конечного положения.
Та же судьба и грань сохраняются в разреженном снимке при депонировании,
а затем используются для удаления/отражения и статистики потерь.
Снимок использует адреса частиц и действителен только до перераспределения
или изменения размера векторов частиц. Обработчик обходит векторы с конца:
переставленная при удалении частица уже обработана.

Для каждого отрезка Esirkepov обеспечивает

`rho(end) - rho(start) + dt * div(J_segment) = 0`.

Длинный отрезок разбивается на смещения не больше ячейки по каждой оси;
нормировка тока остаётся по исходному интервалу. Плотности на внутренних
точках разбиения сокращаются. При поглощении конечный shape на стенке
представляет граничный сток; равенство с нулевой конечной плотностью во всех
ghost cells без этого стока не требуется.

Поддержка широкого stencil в депозите не снимает ограничение
`ParticlesArray::update_cells()`: перераспределение выжившей частицы допускает
только соседние ячейки. Следует выбирать шаг по перемещению частицы.
Текущий отражённый путь описывает одно отражение за полушаг; последовательные
столкновения с несколькими стенками после отражения требуют отдельного mover.

## Ограничение энергии поглощения

Boris в ECSIM-Corr обновляет скорость за полный `dt`, даже если второй сдвиг
пересёк поглощающую стенку раньше конца полушага. `pred_work_` содержит работу
этого полного обновления. `correctv()` исправляет энергию всего сорта;
статистика `LostE` получает энергию удаляемой частицы после коррекции.
Это дискретная учётная энергия схемы, а не вычисленная энергия `K_hit` в
физический момент столкновения. Обрезка Esirkepov-тока обеспечивает
согласованную геометрию заряда, но не превращает mover в энергетически
согласованную модель открытой стенки.

В постоянном ненулевом E физическое время попадания следует находить из
`z_wall = z_start + v_start*t_hit + (q*Ez/(2*m))*t_hit^2`, а скорость из
`v_hit = v_start + (q*Ez/m)*t_hit`. Текущий mover этого не делает.
Для количественной энергии, переданной стенке, нужна отдельная реализация
разбиения шага по событиям и проверка `K_hit` при разных временах выхода,
включая работу поля и поток энергии через границу. Малый глобальный остаток
после коррекции скоростей такой проверкой не является.

## Er0 и дискретное условие Дирихле

Профиль задаёт входящее радиальное поле, `∫ Er dr = -potential_drop`:

- `step`: `Er = -potential_drop/width` в кольце
  `[inner_radius, inner_radius+width]`;
- `cosine`: `Er = -potential_drop/width * (1+cos(2*pi*(r-r0)/width))`
  в `[r0-width/2, r0+width/2]`. Требуется `r0 ≥ width/2`.

`radial_field()` описывает физику профиля. `collect_entries()` вычисляет
Ex/Ey на соответствующих узлах Yee и кеширует предписанные DOF. JSON-режимы
`overwrite` и `solv` сохранены; внутри используются `Er0Mode`.

В `solv` у L-матрицы зануляются только граничные строки. В полной матрице
СЛАУ эти строки заменяются единичными, RHS получает заданное E. Столбцы
сохраняются: свободное уравнение `A_ff*E_f + A_fb*E_b = b_f` должно включать
отклик на известное `E_b`; дополнительно вычитать этот вклад из RHS нельзя.
И предиктор, и корректор используют одну маску. В `overwrite` профиль
перезаписывается после решения, как в исходной реализации.

## Энергетическая диагностика

В обозначениях файлов диагностики знаковый остаток до фильтрации:

`R_raw = ΔK - W_inject - W_emit + ΔU - dt*<E_external,J> + W_lost`.

`er0Work = <E0,J_predictor_raw>` вычисляется до маскирования предикторного
тока. Это учётная мощность отфильтрованных DOF, а не независимо измеренный
поток Пойнтинга и не мощность внешнего электрода.

- `energyResidualRaw = R_raw`;
- `energyResidualDiscrete = R_raw - dt*er0Work`;
- `energyConserve = abs(energyResidualDiscrete)` сохранён для совместимости.

Даже `R_raw` не является полной физической верификацией открытой системы:
`W_lost` имеет описанное выше ограничение, а физическая работа порта и поток
Пойнтинга должны проверяться независимо.

## Двумерная диагностика

Аккумулятор хранит только выбранные плоскости в double. E/B складываются
из компонент непосредственно на плоскостях без временного 3D-поля.
Среднее делится на число отсчётов при записи; отдельная 3D-копия среднего
не создаётся. Память аккумуляторов пропорциональна сумме площадей срезов.
`pressure_2d` пока вычисляет одну компоненту момента во временном скалярном
3D-поле, переиспользуемом для шести компонент; этот проход не оптимизирован
до обхода только нужных плоскостей.

`interval>0` включает обычные файлы, `average_steps>0` — средние независимо
от `interval`. Без обеих опций файлов нет. Шаг 0 входит в окно; неполное
окно дописывается при `finalize()`, повторный вызов не создаёт файлов.
Формат и соглашение индексов срезов сохранены, включая ghost nodes и три
слота компонент в бинарных файлах скалярных величин.
