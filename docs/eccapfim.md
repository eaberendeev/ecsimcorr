# ECCAPFIM: нелинейная схема частиц и поля

Выбор: `Scheme = "eccapfim"`. Реализация использует C++20, Eigen и OpenMP,
без PETSc и MPI. Формулы взяты из периодического варианта
[vakurshakov/xpic](https://github.com/vakurshakov/xpic/tree/dc0ec8b437e00644a116de1f95bf697d170d69b2/src/impls/eccapfim)
на коммите `dc0ec8b437e00644a116de1f95bf697d170d69b2`; код написан на
контейнерах Beren3D. Лицензия источника сохранена в
`srcBeren/simulation/eccapfim/XPIC_LICENSE`.

## Уравнения и временные уровни

Координаты, скорости и поля заданы на целых шагах. В отличие от ECSIM,
начального сдвига координат на полшага нет. На каждой итерации поля частицы
продвигаются заново из неизменного состояния `x_n, v_n`:

```text
v_h = (v_(n+1) + v_n)/2
x_(n+1) = x_n + dt*v_h
v_(n+1) - v_n = dt*(q/m)*(E_orbit[E_h + E_external] + v_h × B_orbit)

M = I + dt²/4 curlB curlE
F(E_h) = M*E_h - E_n - dt/2*curlB*B_n + dt/2*J[E_h] = 0

E_(n+1) = 2*E_h - E_n
B_(n+1) = B_n - dt*curlE*E_h
```

`fieldE/fieldB` — начало шага, `fieldEp` — `E_h`, `fieldEn/fieldBn` — конец.
`fieldJ` — ток траекторий, усреднённый по полному шагу.

Сохранён штатный вариант xpic с `SNES_ITERATE_B=0`: в силе Лоренца
используется **`B_n + B_external`**, а не совместно итерируемое магнитное поле.
Магнитное поле Максвелла обновляется по Фарадею через принятое `E_h`.
Это ограничение варианта метода; совместная нелинейная итерация `E/B`
не реализована. Нелинейность `J[E_h]` включает координаты, скорости и веса
интерполяции. Метод не заменён однократным предиктором ECSIM.

Основной шаг в `SimulationEccapfim::make_step()`:

1. Сохранить частицы начала шага в `Array3D<std::vector<Particle>>`.
2. Решить нелинейное уравнение поля. Каждая невязка повторяет движение всех
   частиц из сохранённых координат и скоростей, обнуляя и собирая ток заново.
3. Обновить электрическое и магнитное поля конца шага.
4. Принять последние траектории, перераспределить частицы и собрать плотность.

Снимки и пробные частицы принадлежат текущему вызову `make_step()` и исчезают
при выходе. Несошедшееся решение вызывает исключение до изменения физических
частиц и `fieldEn/fieldBn`. `fieldEp`, `fieldJ` и параметры сходимости в этом
случае остаются пробными. Restart сохраняет только принятые целочисленные
уровни полей и частиц через существующий recovery; история нелинейного
решателя не сохраняется. Инжекция и сброс событий выполняются в `prepare_step()`;
столкновения — штатно после принятого шага.

## Интерполяция и депозит

Плотность всегда использует квадратичную форму `Shape2`; глобальные `SHAPE`
и `SHAPE_CH` эту схему не переключают. Магнитное поле интерполируется
квадратично с учётом `magnetic_shift(component)`, затем усредняется по
отрезкам траектории. Для электрического поля нужны специальные веса:

```text
W_x(i,j,k) = S1(i+1/2 - x_h) / 6 *
             [S2(j-y_1)*(2*S2(k-z_1)+S2(k-z_0))
              + S2(j-y_0)*(2*S2(k-z_0)+S2(k-z_1))]
```

Координаты здесь измерены в размерах ячейки; `W_y/W_z` получаются
циклической перестановкой координат. Траектория делится на плоскостях
`r_d/h_d = integer + 1/2`. В пределах каждого отрезка оба конца находятся
на одной полиномиальной ветви квадратичной формы. Веса хранятся в обычном
`CurrentBuffer<3>`, формы — в `ParticleShape<Shape2,3>` и
`ParticleShape<Shape,2>`.

Один и тот же `fill_orbit_weights()` используется в gather электрического
поля и депозите тока. Вес отрезка — его доля параметра прямой траектории,
эквивалентная отношению длин. Это обеспечивает одновременно

```text
(rho_(n+1) - rho_n)/dt + div J = 0
sum_grid E_h · J = sum_particles q*mpw*v_h · E_orbit
```

Для нулевого перемещения веса тоже определены. Итерации частицы решают
уравнение скорости с матрицей вращения Boris и проверяют невязку на
принятой траектории. При несходимости интервал частицы делится пополам;
каждый принятый подшаг вносит `dtau/dt` в ток. Поле `E_h` одно на весь шаг.
В отличие от локальных ограничений `update_cells()`, здесь допускаются
длинные траектории; после принятия выполняется полное перераспределение
частиц по ячейкам. Ограничения защиты: 10000 подшагов, 30 делений при
повторном решении и не более 100000 пересечений плоскостей на ось за орбиту.

Нормировка соответствует Beren3D: `mpw = density/NumPartPerCell`, ток
получает `q*mpw*v`, заряд — `q*mpw`. Дополнительного деления на объём ячейки
нет. Энергии также вычисляются в существующей нормировке сумм по сетке.
Нейтральный сорт движется без электромагнитной силы и не входит в ток/заряд.

## Индексы, периодичность и ограничения

В xpic доступ к массиву выглядит как `[z][y][x][component]`, в Beren3D —
`field(i,j,k,component)`, линейный индекс берётся из `Domain::vind()`.
Координаты переводятся через `Domain::to_cell_coordinates()`, положения
компонент совпадают с `electric_shift()/magnetic_shift()`.

Размер массива Beren3D: `N + 2*ghost + 1` на ось. Независимых периодических
узлов ровно `N`, их индексы лежат в `[ghost, ghost+N)`. Индексы траектории
сначала приводятся по модулю `N`, затем добавляется `ghost`. Депозит сразу
направляется владельцам этих узлов с OpenMP atomic; остальные узлы получают
копию. Общий суммирующий периодический обработчик источников после этого
не вызывается: он повторно учёл бы уже свёрнутые вклады.

Оператор `M` берётся из существующего `mesh.IMmat`: выбираются физические
строки, столбцы ghost/дублирующих узлов отображаются на их периодических
владельцев. Формулы curl заново не реализуются. История решателя, нормы
невязок и скалярные произведения содержат только независимые узлы.

Поддержан прямоугольный домен, периодический по всем трём осям, без damping.
Открытые/отражающие границы, er0 и цилиндр явно отклоняются при инициализации.
Их нельзя включать без согласования движения, тока и граничной работы.
Начальное условие Гаусса не исправляется автоматически; сохраняется его
исходная невязка с точностью нелинейного решения. Для периодической плазмы
начальное состояние следует готовить с нулевым суммарным зарядом.

## Решатель и конфигурация

PETSc SNES заменён итерациями Андерсона с ограниченной историей. Направление
шага предварительно обрабатывается решением `M*z=F` через Eigen CG
с допуском `1e-13`; коэффициенты Андерсона находятся QR-разложением.
Остановка проверяет исходную, а не предобусловленную невязку Максвелла:
`||F_k||₂ <= atol + rtol*||F_0||₂`. При превышении числа итераций расчёт
останавливается. Малое изменение поля само по себе не означает сходимость.

Необязательный блок JSON со значениями по умолчанию:

```json
"Eccapfim": {
  "atol": 1e-10,
  "rtol": 1e-10,
  "max_iterations": 200,
  "history": 6,
  "mixing": 0.5,
  "particle_tolerance": 1e-12,
  "particle_iterations": 100
}
```

`history=0` оставляет простые релаксированные итерации. Большой шаг по
времени требует проверки сходимости и точности, даже если схема устойчива;
лимиты решателя не гарантируют сходимость для произвольной плазмы.

В `energy.txt` доступны `nonlinearResidual`, `nonlinearIterations`, работа
внешнего электрического поля и обычные энергетические столбцы.
Для периодического домена без потерь остаток баланса равен
`K_(n+1)-K_n-K_inject + U_(n+1)-U_n - dt*<E_external,J>`.
В энергию динамического магнитного поля входит `B`, а не предписанный
фон `B_external`; его полная энергия выводится отдельно.

## Проверки и пример

```bash
cmake -S srcBeren -B /tmp/beren-eccapfim -DBUILD_TESTS=ON -DCMAKE_BUILD_TYPE=Debug -DUSE_TIMERS=ON
cmake --build /tmp/beren-eccapfim --target eccapfim_invariants beren3d -j 4
ctest --test-dir /tmp/beren-eccapfim -R '^eccapfim_invariants$' --output-on-failure
```

Тест включает точечную непрерывность заряда, согласованность работы
gather/scatter, гиродвижение, волну Максвелла, закон Гаусса, энергию
связанной системы, холодную плазму при большом `dt`, внешнюю электрическую
работу, нейтралы, фактические recovery-файлы и отказ несошедшегося шага.
Сетки анизотропные, число ячеек по осям различается; ядра проверяются
с одним и двумя ghost layers, включая длинные и обратные траектории,
углы, точные полуцелые координаты и периодические переходы.

Небольшой генератор: `tests/integration/eccapfim_basic/gen_config.py`.
Он совместим с `build.py --config ...`; прямой запуск в отдельном каталоге
позволяет использовать уже собранный бинарник без удаления старых расчётов:

```bash
mkdir -p /tmp/beren-eccapfim-run
cd /tmp/beren-eccapfim-run
python3 /absolute/path/to/ecsimcorr/tests/integration/eccapfim_basic/gen_config.py
OMP_NUM_THREADS=2 /tmp/beren-eccapfim/beren3d
```

Периодическая вейбелевская неустойчивость проверена отдельным сценарием
`tests/integration/Weibel_eccapfim/`. Параметры выполненных прогонов,
инкременты, энергобаланс и ограничения статистики приведены в
[отчёте валидации](../tests/integration/Weibel_eccapfim/VALIDATION.md).

Прямое [сравнение с ECSIM-Corr](../tests/integration/Weibel_eccapfim/COMPARISON.md)
содержит парные прогоны при двух `dt`, Release-бенчмарк на общем состоянии
и исправление периодической склейки для одной/двух ячеек.
