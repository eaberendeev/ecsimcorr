# Проверка Вейбеля для ECCAPFIM — 2026-10-26

Проверены реальные расчёты `beren3d`, без PETSc/MPI. Область по X/Y —
`9×9`, сетка `30×30×1`, `dx=dy=dz=0.3`, `dt=1.2`, периодические границы.
Электроны: `T_x=T_y=0.1 кэВ`, `T_z=1 кэВ`, без столкновений и внешнего поля.
Одна ячейка по Z задаёт 2D3V-сценарий с `k_z=0`.

Основной прогон показывает экспоненциальный рост и насыщение магнитной
энергии: максимум `W_B=0.12290` при `ωp t=338.4`. Частицы не терялись,
NaN/Inf не обнаружены. Работа физических стадий основного расчёта заняла
около 299 секунд по встроенному таймеру.

При выполнении процесс автоматически контролировался по конечности данных,
числу частиц, энергобалансу, невязке и числу нелинейных итераций. Предельные
значения для аварийной остановки: относительный дрейф энергии `1e-6`,
остаток баланса шага `1e-7` от начальной энергии, невязка Максвелла `1e-7`,
80 нелинейных итераций, 120 секунд без принятого шага. Ни один предел не
был достигнут. Итоговый checker использует более строгие энергетические
допуски, перечисленные в его JSON-отчёте.

## Интерпретация и ограничения

Инкремент — наклон логарифма **амплитуды**, не энергии. Окно измерения
задано `40…140/ωp`; фактические срезы в нём — `42…138/ωp`, 17 точек.
Ошибка в таблице — формальная стандартная ошибка линейной регрессии;
она не оценивает систематическую ошибку сетки и конечного числа частиц.
Коэффициенты `R²` для `(1,1)` равны 0.869 и 0.807: начальный PIC-шум ещё
заметен. Для основного инкремента задан допуск 20% и значимость не менее 5σ.

Фаза проверяется отдельно в исходном окне `126…270/ωp`, как в общем
`weibel_check.py`. Раннее окно роста включает интерференцию с поперечными
плазменными волнами; его разброс также сохранён в отчёте, но не подменяет
проверку апериодической моды после переходного процесса. Допуск фазы —
исходные 0.6 рад. Срезы читаются с удалением ghost layers и дублирующего
периодического узла; временные метки берутся из `Dt` и интервала выхода.

Спектральные измерения не полностью сошлись по статистике: для `(1,0)`
получены 0.02784 и 0.02533 при теории 0.02034. Для `(0,1)` — 0.02174 и
0.02356 при той же теории. Эти значения доступны в полном отчёте; прохождение
проверки основной моды не означает согласие всех мод с теорией. Более высокая
статистика, проверка по `dt/dx` и независимые реализации начального шума нужны
для точной дисперсионной валидации.

Это уменьшенный физический тест, а не воспроизведение полного исходного
расчёта `30×30×5`, 500 частиц/ячейку. Полный сценарий на 2.25 млн частиц
не запускался. Формулы и допуски существующих схем не менялись;
численные ядра ECCAPFIM в ходе этого теста не потребовали исправлений.

## Воспроизведение

Генератор по умолчанию задаёт основной прогон. Он помечен
`IntegrationHeavy = True`, чтобы не включаться в обычный `--test all`.
Проверку можно вызвать явно через общий runner:

```bash
python3 tests/integration/run_integration.py --test Weibel_eccapfim
```

Или использовать уже собранный бинарник, не удаляя прежние расчёты:

```bash
mkdir -p /tmp/beren-weibel-new
cd /tmp/beren-weibel-new
python3 /absolute/path/to/ecsimcorr/tests/integration/Weibel_eccapfim/gen_config.py
OMP_NUM_THREADS=4 TIMER_END_STEP=0 /tmp/beren-eccapfim/beren3d > run.log 2>&1
python3 /absolute/path/to/ecsimcorr/tests/integration/Weibel_eccapfim/check_weibel.py .
```

Для второго прогона используются 32 частицы/ячейку и `LastTimestep=150`;
остальные физические параметры и окна анализа одинаковы.

Артефакты выполненных расчётов:

- `/tmp/beren-weibel-eccapfim-16/`: `run.log`, `monitor.log`, `energy.txt`,
  срезы, recovery и `Analysis/weibel_eccapfim_report.json`, `Analysis/weibel_eccapfim.png`.
- `/tmp/beren-weibel-eccapfim-32/`: такой же набор для проверки линейной стадии.

Тесты анализа входят в `python_checks`: проверяют исключение ghost nodes
при разных толщинах слоя, отказ усечённого среза и восстановление известного
инкремента синтетической экспоненты. Выполнено 9 Python-проверок, все прошли.
