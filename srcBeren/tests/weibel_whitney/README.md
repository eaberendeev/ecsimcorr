# Сравнение Whitney-ядер на Вейбеле

Это явный численный эксперимент, не часть быстрого CTest-набора.
Исходная задача — `tests/integration/Weibel_ecsim/gen_config.py`:
периодический ящик 30x30x5, h=0.3, dt=1.2, электронные температуры
(0.1, 0.1, 1.0) кэВ и неподвижный нейтрализующий фон. Увеличенное число
начальных частиц принципиально для сохранения анизотропии до линейной стадии.

```bash
cmake -S srcBeren -B /tmp/beren-whitney -DBUILD_TESTS=ON -DCMAKE_BUILD_TYPE=Release -DUSE_TIMERS=ON
cmake --build /tmp/beren-whitney --target weibel_whitney -j 4
python3 tests/integration/Weibel_ecsim/compare_whitney.py \
  --binary /tmp/beren-whitney/tests/weibel_whitney/weibel_whitney \
  --outdir /tmp/weibel-whitney-new-run --ppc 500 --steps 275 --jobs 3 --assembly cell
python3 tests/integration/Weibel_ecsim/analyze_whitney.py /tmp/weibel-whitney-new-run --require-growth
```

Каталог запуска должен быть новым: скрипт не удаляет и не перезаписывает
прежние расчёты. `--steps 275` означает t=330, то есть полную линейную
стадию, но не всю стадию насыщения штатного теста до t=751.2. Для последней
нужно опустить `--steps`. По умолчанию запуск использует 16 частиц/ячейку
только как недорогой шумовой эксперимент; для измерения инкремента явно
указать `--ppc 500`. Никакие параметры сетки или температур не уменьшаются.

`--variants` выбирает из `ecsim`, `point`, `ballistic`, `old_fields`,
`half_drift`, `centered_fields`. Процессы используют непересекающиеся
OpenMP CPU places, сначала на разных физических ядрах; максимальное число
потоков равно `jobs*threads`. Seed распределений Beren фиксирован;
`initial_state.json` содержит независимый от порядка обхода отпечаток
координат и скоростей всех частиц. Перед сравнением отпечатки обязаны совпасть.
Число частиц при 500 на ячейку — 2 250 000.

## Измеряемые величины

- Энергии: обычная нормировка Beren, сумма по физическим узлам без ghost-копий.
  Контролируется конечное время, отсутствие NaN/Inf и относительный дрейф
  полной энергии; порог 1e-3 взят из существующего integration runner.
  Пошаговая абсолютная невязка дополнительно обязана удовлетворять прежнему
  критерию Вейбеля `max|energyConserve|<1e-10`.
- `mode11`: амплитуда трёхмерного Fourier-компонента Bx/By для (kx,ky,kz)=(1,1,0),
  нормированная на число ячеек. Это усреднение по z; штатный старый анализатор
  измеряет один двумерный срез. Для когерентного kz=0 роста оба измерения
  должны быть близки, но их шумовые ошибки различаются.
- Инкремент: наклон ln(mode11) на t=72..270; отдельно половина наклона
  ln(W_B) на t=60..260. Теория вычисляется существующей `gamma_theory`:
  Gamma11≈0.02319, Gamma_max≈0.02359. Выводятся R², окно и формальная ошибка
  OLS-подгонки, которая не заменяет ансамбль независимых начальных состояний.
  `--require-growth` требует исходные диапазоны uncorrected ECSIM:
  Gamma11/theory11 в (0.4,1.15), Gamma_WB/theory_max в (0.25,1.0).
  Эти допуски не ослаблялись. Проверки насыщения и отношения электрических
  энергий из старого отчёта не переносятся на новую схему и укороченную
  линейную стадию. Для шумового опыта на 16 частицах флаг следует опустить;
  сами булевы результаты проверок всё равно сохраняются в JSON.
- `gauss_rms`: RMS div(E^{n+1})-[rho(x^{n+1/2})-mean(rho)] по физическим узлам.
  Вычитание среднего учитывает неподвижный фон. Начальное E=0 сохранено,
  начальные CIC-флуктуации не убираются проекцией.
- `gauss_drift_rms`: RMS изменения этого дефекта относительно начального.
- `density_rms`: sqrt(mean((rho+1)^2)) на всей трёхмерной сетке, без модуля
  перед вычислением дисперсии. Это не та же величина, что std(abs(rho+1))
  одного среза в старом отчёте.
- `continuity_interval_rms`: невязка (rho_b-rho_a)/delta_t+div(J_average),
  где J_average получается интегрированием фактического Maxwell-тока по
  шести шагам между наблюдениями. Источников и столкновений в опыте нет.
- Анизотропия: Tz/Tperp=2*Kz/(Kx+Ky) из штатной energy.txt. Это второй
  момент глобальных скоростей без вычитания локального потока.

Результаты: `summary.json`, `summary.csv`, `comparison.png`,
`comparison.pdf`, `growth_rates.png`. Полные настройки каждого варианта
сохраняются рядом с его `comparison.csv`, energy.txt и картами полей.
`--partial` у анализатора позволяет посмотреть уже завершившиеся варианты;
такой отчёт помечается как частичный.
`seconds` сохраняет длительность конкретного запуска для оценки ресурсов;
сравнивать её как бенчмарк можно только при одинаковом размещении CPU и
одинаковом числе одновременно работающих процессов.

`--profile-step N` сохраняет `step_profile.txt` (дерево времени) и
`step_profile.json` (события потоков) для выбранного шага; требуется
сборка с `USE_TIMERS=ON`. По умолчанию этот вывод отключён. Веса с током
и сборка матрицы замороженного отклика имеют отдельные таймеры по ячейкам.

## Проверка прежних эталонов

Сохранённые расчёты находятся в корне репозитория:

- `Res_Weibel_ecsim_corr_Dx_0.3_np_500_Dt_1.5`: Gamma11≈0.01971,
  все 11 старых проверок проходили.
- `Res_Weibel_ecsim_Dx_0.3_np_500_Dt_1.2`: отчёт содержал Gamma11≈0.01477.
  В старом `weibel_check.py` время срезов было жёстко задано через dt=1.5.
  После исправления чтения реального dt=1.2 и повторной подгонки на физических
  t=72..270 получается Gamma11≈0.01673. Это меняет также набор точек окна,
  поэтому результат нельзя получить одним умножением старого инкремента.

Свежий контрольный ECSIM на 500 частицах/ячейку даёт Gamma11≈0.01651
для kz=0 компонента, что согласуется с архивным ростом. При 16 частицах
исходная анизотропия ~10 уже к t≈100 падает до ~2, и чистого линейного
роста не видно даже в обычном ECSIM. Поэтому завершённые уменьшенные
расчёты до t=751.2 нельзя выдавать за успешную физическую валидацию Вейбеля.
Они пригодны для отдельного сравнения численного шума и невязок.

## Квадратичное ядро на Вейбеле

`compare_whitney.py` содержит варианты `point_q` и `ballistic_q`, которые
выставляют `"WhitneyKernel": "quadratic"`. Сравнение ниже выполнено на полном
штатном числе частиц: 500 частиц/ячейку, 2 250 000 частиц, сетка 30x30x5,
dt=1.2, 2 потока OpenMP, одинаковые начальные частицы (общий fingerprint),
230 шагов до t=276. Окно роста t=72..270.

| Вариант | Gamma11 | Gamma11/theory | Gauss RMS | Gauss drift | density RMS at t≈100 | max relative dE | с/шаг | всего, с |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| ECSIM | 0.016513 | 0.712 | 0.1831 | 0.1762 | 8.91% | 1.54e-12 | 1.24 | 285 |
| point linear | 0.020255 | 0.874 | 0.02823 | 0.02279 | 2.48% | 8.01e-12 | 1.55 | 357 |
| point quadratic | 0.020970 | 0.904 | 0.01835 | 0.00406 | 1.75% | 7.40e-13 | 15.03 | 3456 |

Квадратичное ядро даёт рост, близкий к полному symplectic-прогону
(0.02096) и выше полного ECSIM-Corr (0.01971), но в этом контролируемом
2-поточном сравнении оно примерно в 9.7 раза медленнее линейного point и в
12 раз медленнее ECSIM. Основная цена — более плотная матрица L: после
группировки по восьми S2-базисам внутри ячейки число triplet'ов перестаёт
зависеть от числа частиц, но остаётся существенно больше линейного 12x12.
Полный прогон 230 шагов занимает около 58 минут на двух потоках; для
production-расчёта до насыщения нужна дальнейшая оптимизация сборки/солвера.

Короткий прогон 16 частиц/ячейку, 20 шагов (включая инициализацию) даёт
ориентировочное отношение: point 0.23 с/шаг, point_q 4.82 с/шаг,
ballistic 0.62 с/шаг, ballistic_q 5.45 с/шаг. Абсолютные значения нельзя
сравнивать с таблицей 500 ppc напрямую: при малом числе частиц время шага
определяется фиксированной по сетке сборкой матрицы.

## Сборка замороженного отклика

`--assembly cell` включает `WhitneyOrbit.assembly=cell` для замороженных
вариантов и `WhitneyAssembly=cell` для точечного Whitney. У точечного
варианта параллельны сборка 12x12 по ячейкам и толчок; у замороженных —
сборка и толчок с сохранёнными интегральными весами. В обоих случаях
ток каждого потока накапливается в своём буфере и суммируется после барьера.
`--assembly reference` сохраняет последовательный эталон.

В замороженных вариантах суммируются те же
Wbar^T alpha Wbar, но повторяющиеся элементы внутри ячейки объединяются
до сортировки Eigen. Скалярные веса, магнитный отклик, ток и траектории
не меняются. У каждой ячейки свой набор рёбер, полученный из фактических
интегральных весов, без предположения о 12-точечном stencil.

Эталон `assembly=reference` сохранён и остаётся значением по умолчанию
для самой simulation. Проверки `ecsim_whitney` сравнивают полные матрицы
и токи обоих способов, а также независимо проверяют Boris-ток и работу
поля для всех четырёх предикторов. Если объединённый набор рёбер превышает
256 DOF, сборка автоматически использует разреженный эталонный путь.

В клеточной сборке независимые ячейки выполняются через OpenMP с локальными
токами и triplets каждого потока. Префиксные диапазоны частиц заранее
выделяют непересекающиеся места в буфере отклика; общих push_back и записей
тока без синхронизации нет. После барьера токи складываются, а матрица
собирается обычным способом. Ошибка орбиты внутри потока передаётся вызывающей
simulation после барьера. Эталонный путь остаётся последовательным.
Веса магнитных граней после вычисления Bbar не сохраняются: между сборкой
и толчком нужны только электрические веса и уже собранное Bbar.

На двух штатных шагах с 2,25 млн частиц последовательная клеточная и
параллельная клеточная сборки сравнены с исходными per-particle triplets:
отпечатки частиц совпадают, максимальные различия всех записанных величин
не превышают 2e-15. Отдельно прошли одно- и двухпоточные проверки ядер.

## Измерение параллельного толчка и точечной сборки

Локальный замер 30.10.2026: 500 частиц/ячейку, 2 250 000 частиц,
dt=1.2, два OpenMP-потока на одинаковых CPU. Варианты запускаются
последовательно (`--jobs 1`), диагностики одинаковы. Время на шаг
вычислено по разности накопленного времени на шагах 60 и 20; начальные
20 шагов исключены. До правки выполнено 120 шагов, после — 60, для
сравнения используется только общий интервал 20..60.

| Вариант | До, с/шаг | После, с/шаг | Ускорение |
| --- | ---: | ---: | ---: |
| ECSIM (контроль) | 1.1212 | 1.1220 | 1.00 |
| Точечный Whitney | 1.9343 | 0.9432 | 2.05 |
| Ballistic, клеточная сборка | 4.0793 | 3.9945 | 1.02 |

У точечного Whitney распараллелены сборка отклика и толчок, а gather и
scatter толчка используют одни вычисленные электрические веса. У
замороженного варианта дополнительно распараллелен толчок. Все записанные
энергии, нормы невязок, плотности и амплитуды мод на t=0..72 отличаются
от прежнего запуска менее чем на 5e-13. Фаза слабой моды проверяется
совместно с амплитудой, поскольку при нулевой амплитуде угол не определён.
Отдельно прошли проверки полного отклика, токов, скоростей и работы поля
с одним и двумя потоками, а также 23 быстрых CTest-теста.

Это один замер каждого варианта с диагностиками, не изолированный
бенчмарк ядра и не оценка разброса между запусками. Новые расчёты до
насыщения, проверка файлового restart и ансамбль seed не выполнялись.

## Аналитическое интегрирование замороженных весов

При `assembly=cell` сохранён тот же точный интеграл форм вдоль предсказанной
траектории, но внутри каждого пересечённого элемента он вычисляется
аналитически. Прямая внутри одной ячейки не требует объединения весов.
Рабочие векторы потоков и ёмкости электрических весов частиц используются
повторно. Значения отклика после толчка недействительны; следующая сборка
записывает их заново с учётом текущих корзин и числа частиц.

На тех же 2 250 000 частицах и двух CPU, последовательно, по шагам 20..60:

| Ballistic | Время, с/шаг |
| --- | ---: |
| Квадратура Гаусса и прежние выделения памяти | 3.9945 |
| Аналитический интеграл и повторное использование памяти | 2.4175 |

Ускорение — 1.65 раза. Энергии, нормы невязок, плотности и амплитуды мод
на t=0..72 отличаются менее чем на 4.1e-13; максимальный относительный
дрейф энергии — 6.9e-14. Это один запуск, без оценки разброса времени.
Профиль последнего шага оптимизированного варианта: около 0.46 с на
веса с предикторным током, 0.59 с на локальные матрицы, 0.58 с на решение
поля и 0.16 с на толчок. Для параллельных участков указана большая из сумм
времён двух потоков; эти значения не заменяют полное время шага.

Проверены полные матрицы и токи против последовательного эталона для
всех четырёх предикторов, работа поля, независимая непрерывность CIC-тока,
веса при обратном движении, угловых и периодических пересечениях и
нескольких обходах домена. Проверка срока жизни кеша включает повторный
толчок и добавление частиц между шагами. Прежняя квадратура и сборка
`assembly=reference` сохранены. Расчёт до насыщения, файловый restart
и ансамбль seed после этой оптимизации не запускались.
